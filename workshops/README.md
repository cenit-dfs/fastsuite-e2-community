# Workshops

Self-contained workshop scenarios for learning E2 downloader development with Copilot.

Each folder holds everything needed for one workshop exercise: an E2 scenario, reference data, expected output, and controller documentation.

## Available Workshops

| Folder | Vendor | Technology | Description |
|--------|--------|------------|-------------|
| `KAWASAKI_ArcWelding/` | Kawasaki | Arc Welding | AS language downloader with touch sensing |

## Folder Structure (per scenario)

```
workshops/<VENDOR>_<Application>/
├── README.md                        ← exercise overview, goals, instructions
├── scenarios/
│   └── <name>.cendoc                ← E2 project file (binary, Git LFS)
├── reference/
│   ├── <name>_tree.txt              ← Simple Translator dump of the .cendoc
│   └── <name>_cd.xml                ← Legacy CD XML stylesheet (attribute mapping)
├── golden/
│   ├── program1.as                  ← expected downloader output
│   └── ...
└── docs/
    ├── <vendor>_language_ref.md      ← robot programming language reference
    └── ...                           ← additional docs (touch sensing, etc.)
```

### What goes where

| Content | Folder | Format | Notes |
|---------|--------|--------|-------|
| E2 project | `scenarios/` | `.cendoc` | Binary, 10-20 MB, tracked via Git LFS |
| OLP tree dump | `reference/` | `.txt` | Generated by `Simple_Python_Translator.py` — agent-readable |
| Legacy CD XML | `reference/` | `.xml` | Shows which E2 attributes map to which output constructs |
| Expected output | `golden/` | vendor-specific | The exact files the new downloader should produce |
| Controller docs | `docs/` | `.md` | Robot language spec — the agent needs this to generate correct syntax |

## Adding a New Workshop Scenario

1. Create a folder: `workshops/<VENDOR>_<Application>/`
2. Follow the structure above
3. Write a `README.md` with exercise goals and step-by-step instructions
4. Commit the `.cendoc` via Git LFS (`git lfs install` once, then commit normally)
5. Open a PR to the community repo
